# Проект 3. Сервис FastAPI для генерации коротких ссылок

## Описание

Реализация проекта 3 по предмету прикладной Python - генарция коротких ссылок. Автор - Д. Васильев.

---

**Функционал сервиса:**

1. Создание короткой случайно сгенерированной ссылки на основе оригинального URL. Каждая новая ссылка уникальна и имеет длину в 6 символом, состоящих из латинских букв и цифр
2. Возможность создания кастомной ссылки (алиаса) на основе оригинального URL. Вариант доступен авторизированным пользователям.
3. Возможность создания кастомной ссылки с конкретным сроком до удаления. По умолчанию срок действия всех кастомных ссылок - 14 дней со дня создания (после - автоудаление). Доступно для зарегестриванных пользователей
4. Возможность перейти по короткой  ссылке или алиасу, ранее сгенерированным (перенаправление по оригинальному URL)
5. Удаление ранее созданной короткой ссылки или алиаса. Вариант доступен авторизированным пользователям
6. Изменение привязки сгенерированной ссылки или алиаса к другому URL
7. Получение статистики по использованию конкретной короткой ссылке или алиасу: привязка к оригинальному URL, дата создания,
8. Поиск кастомной ссылки по оригинальному URL
9. Регистрация и авторизация пользователя. Для этого используется аутентификация на основе JWT и хеширование паролей с помощью Bcrypt (*Secure Token-based Authentication*)
10. Хранение информации о пользователях производится в БД PostgreSQL
11. Также дополнительно используется Redis для кэширования наиболее часто используемых ссылок. Кэш чистится при удалении/изменении записей в БД

## Схема БД

* Таблица links (Хранение активных ссылок)
  * id - id записи
  * orig_url - исходный URL
  * short_code - короткая сгенерированная ссылка
  * custom_alias - вариант алиаса ссылки от пользователя
  * created_dt - дата создания
  * expires_dt - дата истечения срока хранения
  * last_accessed_dt - дата последнего обращения (перехода по ссылке)
  * click_cnt - количество переходов по ссылке
  * user_id - id пользователя, создавшего ссылку (если через зарегистрированного)
  * project - наименование проекта (группы ссылок)
* Таблица users (Хранение пользовательских данных)
  * id - id зарегистрированного пользователя
  * email - почтовый адрес пользователя
  * password_hash - хэш пароля пользователя
* Таблица expired_links (хранение ссылок с истёкшим сроком действия)
  * id - индекс записи
  * orig_url - исходный URL
  * short_code - алиас/короткий сгенерированный код под исходный URL
  * expired_dt - дата истечения срока хранения в links

## Слой кэширования Redis

Для быстрого ответа по запросу к наиболее часто используемым ссылкам в проекте присутствует слой Redis формата `Key-Value`

## Запуск проекта

Для запуска проекта необходимо выполнить 5 шагов:

1. Создать собственное виртуальное окружение и установить зависимости. Для проекта рекомендуется версия Python >= 3.10

   ```
   python -m venv .venv

   source .venv/bin/activate

   pip install -r requirements.txt
   ```
2. Создать собственный файл .env зависимостей проекта. Мой пример:

   ```
   DB_URL=postgresql+psycopg2://postgres:postgres@localhost:5432/links_db
   REDIS_URL=redis://localhost:6379
   JWT_SECRET=supersecret
   DEFAULT_UNUSED_DAYS=30
   ```
3. Выполнить докер сборку проекта

   ```
   docker compose up -d
   ```
4. Инициализировать БД в текущей сборке

   ```
   python init_db.py
   ```
5. Запустить проект

   ```
   uvicorn main:app --reload
   ```

## Пример запросов

Запросы можно делать как непосредственно через bash или другую командую оболочку, так и через Postman. Для наглядности будут приведены курлы для bash:

* Регистрация пользователя

```
Посылка:
curl-X POST http://127.0.0.1:8000/auth/register
-H**"Content-Type: application/json"**
-d**'{**
"email":"mail@mail.com",
"password":"123456"
}'

Ответ:
{
 "user_id": 1
}
```

* Авторизация и получение JWT токена

```
Посылка:
curl -X POST http://127.0.0.1:8000/auth/login \
-H "Content-Type: application/json" \
-d '{
"email":"mail@mail.com",
"password":"123456"
}'

Ответ:
{
 "access_token": "какойтодлинныйтокен9нужноскопироватьдляиспользования"
}
```

* Создание короткой ссылки без авторизации

```
Посылка:
curl -X POST http://127.0.0.1:8000/links/shorten \
-H "Content-Type: application/json" \
-d '{
"orig_url":"https://hse.ru"
}'

Ответ:
{
 "short_url":"http://localhost:8000/какойтокодна6символов"
}
```

* Создание кастомной ссылки зарегистрированным пользователем

```
Посылка:
curl -X POST http://127.0.0.1:8000/links/shorten \
-H "Authorization: Bearer какойтодлинныйтокен9которыйвысохранили" \
-H "Content-Type: application/json" \
-d '{
"orig_url":"https://github.com",
"custom_alias":"gh"
}'

Ответ:
{
 "short_url":"http://localhost:8000/gh"
}
```

* Создание ссылки с TTL (датой "сгорания")

```
Посылка:
curl -X POST http://127.0.0.1:8000/links/shorten \
-H "Authorization: Bearer какойтодлинныйтокен9которыйвысохранили" \
-H "Content-Type: application/json" \
-d '{
"orig_url":"https://stackoverflow.com",
"expires_dt":"2026-12-31"
}'
```

* Переход по кастомной/сгенерированной ссылке

```
Посылка:
curl -v http://127.0.0.1:8000/gh

Ответ:
HTTP/1.1 307 Temporary Redirect
location: https://github.com
```

* Вывод статистики

```
Посылка:
curl http://127.0.0.1:8000/links/gh/stats

Ответ:
{
 "orig_url":"https://github.com",
 "created_dt":"ваша дата создания",
 "click_cnt":числоперходов,
 "last_accessed_dt":"последняя дата использования"
}
```

* Поиск алиаса по оригинальному URL

```
Посылка:
curl "http://127.0.0.1:8000/links/search?original_url=https://github.com"

Ответ:
[
 {
  "short_code":"gh",
  "orig_url":"https://github.com"
 }
]
```

* Изменение привязки алиаса к другому URL с авторизацией

```
Посылка:
curl -X PUT http://127.0.0.1:8000/links/gh \
-H "Authorization: Bearer ваштокен" \
-H "Content-Type: application/json" \
-d '{
"orig_url":"https://gitlab.com"
}'

Ответ:
{
 "user_id": 1
}
```

* Удаление ссылки её авторизированным владельцем

```
Посылка:
curl -X DELETE http://127.0.0.1:8000/links/gh \
-H "Authorization: Bearer ваштокен"

Ответ:
{
 "message":"Link deleted"
}
```

# Проект 4. Тестирование API-сервиса

## Описание

Проект по покрытию тестами проекта 3. Покрытие реализовано в `./tests`, структура приведена в проекте 3, раздел "**Структура проекта**"

---

## Разновидности тестов

1. Unit-тесты (`./tests/unit/`)

   1. `test_link_generator.py` - тестирование длины и уникальности сгенерированных ссылок
   2. `test_link_service.py` - сервисы по созданию кастомной и рандомной ссылок
2. Функциональные тесты `(./tests/api`/)

   1. Для тестов в файле `./tests/conftest.py` создаётся фикстура БД в локальной сессии
   2. `test_auth.py` - тестирование аутенфикации и регистрации
   3. `test_link_api.py` - тестирование основных функций сервиса (описание приведено в проекте 3)
3. Нагрузочные тесты *Locus (`./tests/load/`)*

   1. `locusfile.py` - нагрузочный тест *Locus* для множественного создания ссылок

   ---

## Запуск и проверка покрытия

* Нагрузочный тест *Locus*

  ```
  locust -f tests/load/locustfile.py
  ```
* Запуск *Pytests*

  ```
  coverage run -m pytest tests

  ```
* Проверка покрытия

  ```
  coverage report или coverage html
  ```
